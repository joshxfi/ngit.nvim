1. INTRODUCTION                                               *ngit-introduction*

ngit displays Changes, Branches, Commits, and Stashes in persistent native
Neovim windows on the left and a lazy-loaded structured diff on the right.
The diff uses aligned old/new panes when space allows and a polished unified
view in narrower windows. A one-line footer shows actions relevant to the
focused panel.

Requirements:
  - Neovim 0.10 or newer
  - Git

==============================================================================
2. COMMANDS                                                       *ngit-commands*

                                                              *:NGit*
:NGit [directory]
        Open ngit for the repository containing [directory]. Without an
        argument, use the current buffer and then the current working
        directory. If a view is already open, focus it.

                                                              *:NGitRefresh*
:NGitRefresh
        Refresh the active repository view.

                                                              *:NGitClose*
:NGitClose
        Close the active view and return to the previous tabpage.

                                                              *:NGitLog*
:NGitLog
        Open ngit and focus the paginated Commits panel.

                                                              *:NGitBranches*
:NGitBranches
        Open ngit and focus the local and remote Branches panel.

                                                              *:NGitStashes*
:NGitStashes
        Open ngit and focus the Stashes panel.

                                                              *:NGitReview*
:NGitReview [range]
        Open ngit in review mode for [range]. Without an argument, review this
        branch against its upstream. See |ngit-review|.

                                                              *:NGitBlame*
:NGitBlame [file]
        Annotate [file], or the current buffer, with its commit authorship.

                                                              *:NGitHistory*
:NGitHistory [file]
        Narrow the Commits panel to the history of [file], or of the current
        buffer, following it across renames.

3. MAPPINGS                                                       *ngit-mappings*

Mappings are local to ngit-owned buffers. Every one of them can be rebound, or
disabled by setting it to false; see |ngit-configure|.

s, u, and X also exist in visual mode. Over the Changes panel a selection acts
on every file it covers; over the diff it acts on exactly the added and removed
lines it covers, the way `git add -p` splits a hunk.

k               Select the previous item in the focused panel.

<Esc>           Return from the preview to the active panel.

4. REVIEW MODE                                                      *ngit-review*

Review mode points the Changes panel at a revision range instead of the working
tree. Press gr, or run |:NGitReview|, and the panel lists the files that range
touches under a Range heading while the preview diffs each one across it.

Without an argument the range is this branch against its upstream, falling back
to origin/HEAD and then to a local main, master, develop, or trunk. The
three-dot form is always used, so the answer is the work this branch adds rather
than everything that landed on the base meanwhile.

Range entries have no index and no worktree side, so s, u, and X are refused
while review mode is active and say so. gr offers the way back out, and the
panel detail names the range for as long as it is on.

gh follows one file instead: the Commits panel narrows to `git log --follow` for
that path, and each commit's preview narrows to the same path. gB annotates the
file with `git blame` in a float, where <CR> on a row reveals that commit in the
Commits panel, paging the history forward until it is found.

The Commits filter understands server-side queries as well as substrings. A
filter naming any of author:, grep:, message:, path:, file:, since:, after:,
until:, before:, or all:true is answered by Git over the whole history; values
may be quoted. Anything else stays an instant substring match over the rows
already loaded.

==============================================================================
5. REWRITING HISTORY                                               *ngit-rewrite*

gi opens an interactive rebase plan: one row per commit, oldest first, with p, r,
e, s, f, and d setting pick, reword, edit, squash, fixup, and drop, <Tab> cycling
through them, J and K reordering, and <C-s> running the result.

reword has no todo verb that carries a new message, and driving an editor from
inside an asynchronous job is not something ngit will do, so a reword becomes a
pick followed by `break`. The rebase stops with that commit at HEAD, where C
amends it and gC continues. edit stops the same way with the commit applied. A
squash keeps Git's combined message; amend it afterwards if that is not what you
wanted.

gi also offers autosquash, which lets Git build the todo itself so that fixup!
and squash! subjects fold into the commits they name. gc creates those commits:
it offers `--fixup` and `--squash` against the selected commit, alongside
--signoff, --no-verify, --gpg-sign, --allow-empty, amend --no-edit, and
rewording HEAD.

gR resets onto the selection, naming what each mode keeps; a hard reset is
confirmed separately. gv reverts the selected commit. gx checks a commit out with
a detached HEAD.

Rewritten history cannot be pushed with a plain push. gm offers
`--force-with-lease`, which refuses when the remote has moved since the last
fetch. Plain --force is not offered at all.

6. CONFLICTS                                                     *ngit-conflicts*

co, ct, and cb take ours, theirs, or both sides. Pressed in the Changes panel
they act on the whole file; pressed in the diff they resolve only the conflict
block the cursor sits in, so one file can take ours here and theirs there. ]x
and [x move between the blocks.

Taking a side for a whole file goes through `git checkout --ours`, which restores
the recorded stage exactly, including a file one side deleted. The per-block form
rewrites the file, preserving whether it ended with a newline, and stages it only
once no markers are left, so a partly resolved file is never marked resolved.
Both diff3 and merge marker styles are understood.

7. CONFIGURATION                                                 *ngit-configure*

Configuration is optional. Defaults work without calling setup().

>lua
  require("ngit").setup({
    context = 3,
    debounce_ms = 45,
    refresh_debounce_ms = 120,
    max_diff_bytes = 2 * 1024 * 1024,
    cache_entries = 24,
    max_cache_bytes = 32 * 1024 * 1024,
    commit_limit = 150,
    layout = "dashboard",
    diff_layout = "auto",
    side_by_side_min_width = 80,
    file_panel_width = 0.32,
    file_panel_height = 0.35,
    hide_statusline = true,
    auto_refresh = true,
    confirm_discard = true,
    ignore_whitespace = false,
  })
<

context
        Number of context lines generated around each diff hunk. d+ and d-
        adjust it for the open view without changing this default.

debounce_ms
        Delay before loading a newly selected file diff.

refresh_debounce_ms
        Delay used to coalesce automatic repository refreshes.

max_diff_bytes
        Soft preview size limit. Hunk actions are disabled for truncated
        previews.

cache_entries
        Maximum number of preview models retained in memory.

max_cache_bytes
        Maximum estimated memory retained by cached preview models. A single
        preview larger than this budget is displayed but not cached.

commit_limit
        Number of commits loaded per page. Press L to load another page.

layout
        The default is "dashboard", keeping all repository panels visible and
        the patch on the right. Former values "vertical", "stacked", and
        "auto" remain accepted as compatibility aliases and normalize to the
        dashboard.

diff_layout
        "auto", "side_by_side", or "unified". Auto uses aligned old/new panes
        when the preview has enough space and unified presentation otherwise.

side_by_side_min_width
        Minimum preview width used by the automatic side-by-side layout.

hide_statusline
        Collapse native split statuslines into one blank global row while the
        ngit tab is active. If lualine is loaded, its statusline renderer is
        suspended. The previous statusline mode is restored when leaving or
        closing ngit.

file_panel_width
        A fraction below 1, or an absolute window width.

file_panel_height
        Retained for configuration compatibility. Dashboard panel heights are
        allocated automatically from the available editor height.

auto_refresh
        Refresh an open view after buffer writes, shell commands, and focus
        changes. Buffer writes reload working-tree status only; shell and focus
        events reload every repository collection.

confirm_discard
        Ask before discarding. The prompt names the exact effect, which
        depends on the section the file is selected in.

ignore_whitespace
        Start with whitespace-only changes collapsed, as `dw` toggles.
        --ignore-space-change is used rather than --ignore-all-space, so a
        change in indentation is still shown: in an indentation-sensitive
        language that is a change in meaning, not noise. Either form prints the
        collapsed text of a demoted line, which Git cannot then place, so hunk
        and line actions are disabled while the option is on.

signs
        Text displayed for each file state, including `range` for the rows
        review mode lists.

mappings
        Buffer-local mappings. Set a mapping to false to disable it. Actions
        reached through a menu are mapped and listed under `?` but kept out of
        the one-line footer, which has room only for the everyday keys.

8. HIGHLIGHTING                                               *ngit-highlights*

Diff lines use NgitDiffAdd, NgitDiffDelete, and NgitDiffChange. Changed text
within a line uses NgitDiffAddText or NgitDiffDeleteText.
NgitDiffAddNumber and NgitDiffDeleteNumber color the source line numbers beside
added and removed rows; no +/- marker is drawn, as the tint carries the side.
Headers and alignment rows use NgitDiffHeader and NgitDiffFiller. Source
syntax highlighting is enabled when a preview contains one recognizable file
type.

An alignment row, where one side of a split has no matching line, is tinted
only when Normal has a background. A transparent colorscheme leaves Normal
unpainted, and inventing a backdrop for it would put an opaque block over the
terminal. Added and removed rows keep their background either way, since that
tint is what identifies the side.

The commits panel lists the abbreviated hash and subject only. A commit's
author and full date are the first lines of its preview, so the panel spends
its width on the subject. Stashes keep a compact age, because `git stash show`
prints no header for one to live in.

Dashboard fields use NgitCommitHash, NgitCommitType, NgitDate, NgitDecoration,
NgitBranchLocal, NgitBranchRemote, NgitUpstream, NgitStashRef, NgitPath, and
NgitPathDim for the leading directories of a path. Commit metadata above a
patch uses NgitDiffMeta, and source line numbers use NgitLineNr.
File markers use the foreground-only NgitStagedSign, NgitUnstagedSign,
NgitUntrackedSign, NgitConflictSign, and NgitRangeSign groups; the matching
section headings reuse them through NgitStaged, NgitUnstaged, NgitUntracked,
NgitConflict, and NgitRange. Review rows take a muted accent, because unlike the
other four they are read-only.
Panel headers read "[2] Branches", where the bracketed number is the key that
focuses that panel. They use NgitPanelActive, NgitPanelIndex, NgitPanelMarker,
NgitPanelMarkerIdle, and NgitPanelCount; the index and title stay muted until
the panel is focused. The action bar uses NgitActionKey and NgitActionLabel.
Unfocused panels dim their selection through NgitCursorLineIdle.
The footer's result message uses NgitSuccess or NgitFailure, the key sheet's
titles use NgitHeader, secondary text throughout uses NgitMuted, and the window
statusline ngit installs over its own splits uses NgitStatusline.
All groups may be overridden after setup(). Theme-derived diff backgrounds are
recomputed after :colorscheme while they remain ngit-owned; an explicit user
override is preserved.

9. SAFETY AND PERFORMANCE                                         *ngit-safety*

Git is invoked asynchronously with argument arrays and literal pathspecs.
Read-only commands avoid optional repository locks. Status is parsed from
NUL-delimited porcelain-v2 output.

--literal-pathspecs is what keeps a file called `:(top)name.txt` from being read
as pathspec magic. A few porcelain commands build pathspecs of their own, though:
`git stash push --keep-index` runs an internal checkout against `:/`, which the
literal flag makes Git reject. Those callers opt out of the flag and mark their
own paths with the per-pathspec `:(literal)` prefix instead, so the guarantee is
unchanged.

Narrowing a patch to a hunk or to selected lines rewrites the rows that were not
chosen rather than dropping them: whichever side the target already holds has to
survive as context, and whichever side it does not must disappear. Staging and
unstaging the same selection therefore produce different patches. The rows are
also re-paired, because Git prints every removal of a change block before every
addition; emitting them in stream order would place a kept line after the context
its neighbours turned into, and the staged file would carry it in the wrong
place. Splitting a whole-file addition or deletion is refused outright, since
reversing a creation rewrites the whole file rather than a range inside it.

Changes, branches, commits, and stashes load independently and asynchronously.
Only the active panel's selected file, commit, branch, or stash preview is
loaded. Changing panel focus does not reload collection data. Commit history is
paginated. Rapid selection changes are debounced, superseded jobs are
terminated, and recent previews are stored in a cache bounded by both entry
count and estimated bytes. Oversized previews are displayed without caching.
Each raw patch is parsed once into a semantic presentation model, and the last
few models are retained so moving back over a file redraws without rebuilding
them. Toggling between split and unified presentation does not run another Git
command. Unified presentation is built lazily only when it is displayed. On
narrow screens the preview falls back to unified mode; editor areas smaller
than 40 columns by 16 lines are rejected before any dashboard tab is created.

Source line numbers are drawn through 'statuscolumn', so a patch costs nothing
for the rows that are never displayed. Syntax highlighting is skipped for very
large previews. Detecting an in-progress merge, rebase, cherry-pick, or revert
stats the git directory instead of spawning a process per refresh, and writes
outside the repository do not trigger one.

Every discard is confirmed and states its exact effect, deleting an untracked
file only when that is what was asked for. A file with unsaved changes in a
loaded buffer is never overwritten, and buffers are rechecked after any
mutation. Renames are acted on through both of their paths so no half-staged
entry is left behind. Branch deletion asks Git first and only offers the forced
form once Git has reported the branch unmerged, naming what would be lost. The
default pull is fast-forward-only. The only forcing push offered is
--force-with-lease, which refuses when the remote moved since the last fetch;
plain --force is not exposed. Deleting a remote branch says that it affects
everyone using it. Remote progress appears in a cancellable floating console.

Review mode is read-only by construction: a revision range has no index and no
worktree side, so staging and discarding are refused there rather than passed to
Git. Resolving one conflict block at a time stages the file only once no markers
remain, so a partly resolved file is never marked resolved, and the rewrite
preserves whether the file ended with a newline.

Failures report what Git actually said. Several ordinary refusals arrive on
standard output rather than standard error, so both are considered before
falling back to an exit code. Committing checks for unresolved conflicts and
an empty index before opening an editor.
