1. INTRODUCTION                                               *ngit-introduction*

ngit displays Changes, Branches, Commits, and Stashes in persistent native
Neovim windows on the left and a lazy-loaded structured diff on the right.
The diff uses aligned old/new panes when space allows and a polished unified
view in narrower windows. A one-line footer shows actions relevant to the
focused panel.

Requirements:
  - Neovim 0.10 or newer
  - Git

==============================================================================
2. COMMANDS                                                       *ngit-commands*

                                                              *:NGit*
:NGit [directory]
        Open ngit for the repository containing [directory]. Without an
        argument, use the current buffer and then the current working
        directory. If a view is already open, focus it.

                                                              *:NGitRefresh*
:NGitRefresh
        Refresh the active repository view.

                                                              *:NGitClose*
:NGitClose
        Close the active view and return to the previous tabpage.

                                                              *:NGitLog*
:NGitLog
        Open ngit and focus the paginated Commits panel.

                                                              *:NGitBranches*
:NGitBranches
        Open ngit and focus the local and remote Branches panel.

                                                              *:NGitStashes*
:NGitStashes
        Open ngit and focus the Stashes panel.

3. MAPPINGS                                                       *ngit-mappings*

Mappings are local to ngit-owned buffers.

q               Close the view.
r               Refresh status and the selected diff.
j               Select the next item in the focused panel.
k               Select the previous item in the focused panel.
<CR>            Focus the selected diff.
<Esc>           Return from the preview to the active panel.
<Tab>           Focus the next dashboard panel.
<S-Tab>         Focus the previous dashboard panel.
1               Focus Changes.
2               Focus Branches.
3               Focus Commits.
4               Focus Stashes.
]c              Jump to the next hunk.
[c              Jump to the previous hunk.
]f              Jump to the next changed file in the preview.
[f              Jump to the previous changed file in the preview.
dv              Toggle side-by-side and unified diff layouts.
s               Stage the selected file, or current hunk in the diff.
u               Unstage the selected file, or current hunk in the diff.
a               Stage every change. Applies in the Changes panel.
A               Unstage every change. Applies in the Changes panel.
X               Discard the selected change after confirmation. An unstaged
                file returns to its staged content, a staged file returns to
                HEAD, and an untracked file is deleted. Conflicts are refused.
o               Open the selected file.
/               Filter the file list.
<Leader>e       Focus the file panel.
0               Focus the selected diff.
?               Open the key sheet in a floating window.
gs              Focus Changes.
gl              Focus paginated Commits.
gb              Focus local and remote Branches.
gz              Focus Stashes.
x               Switch branch, or copy a commit hash.
n               Create a branch or stash.
a               Apply the selected stash. Applies in the Stashes panel.
p               Pop the selected stash.
D               Delete a merged local branch or drop a stash.
L               Load another page of commits.
c               Create a commit in a gitcommit buffer.
C               Amend HEAD in a gitcommit buffer.
f               Fetch all remotes and prune stale refs.
U               Pull with fast-forward-only semantics.
P               Push normally. Force push is not exposed. When the branch has
                no upstream, ngit offers to push with --set-upstream instead
                of failing.
co              Resolve the selected conflict with ours and stage it.
ct              Resolve the selected conflict with theirs and stage it.
gC              Continue an active merge, rebase, cherry-pick, or revert.
gA              Confirm and abort the active Git operation.
m               Merge the selected branch into the current branch.
R               Rebase the current branch onto the selected branch.
v               Cherry-pick the selected commit.

4. CONFIGURATION                                                 *ngit-configure*

Configuration is optional. Defaults work without calling setup().

>lua
  require("ngit").setup({
    context = 3,
    debounce_ms = 45,
    refresh_debounce_ms = 120,
    max_diff_bytes = 2 * 1024 * 1024,
    cache_entries = 24,
    max_cache_bytes = 32 * 1024 * 1024,
    commit_limit = 150,
    layout = "dashboard",
    diff_layout = "auto",
    side_by_side_min_width = 80,
    file_panel_width = 0.32,
    file_panel_height = 0.35,
    hide_statusline = true,
    auto_refresh = true,
    confirm_discard = true,
  })
<

context
        Number of context lines generated around each diff hunk.

debounce_ms
        Delay before loading a newly selected file diff.

refresh_debounce_ms
        Delay used to coalesce automatic repository refreshes.

max_diff_bytes
        Soft preview size limit. Hunk actions are disabled for truncated
        previews.

cache_entries
        Maximum number of preview models retained in memory.

max_cache_bytes
        Maximum estimated memory retained by cached preview models. A single
        preview larger than this budget is displayed but not cached.

commit_limit
        Number of commits loaded per page. Press L to load another page.

layout
        The default is "dashboard", keeping all repository panels visible and
        the patch on the right. Former values "vertical", "stacked", and
        "auto" remain accepted as compatibility aliases and normalize to the
        dashboard.

diff_layout
        "auto", "side_by_side", or "unified". Auto uses aligned old/new panes
        when the preview has enough space and unified presentation otherwise.

side_by_side_min_width
        Minimum preview width used by the automatic side-by-side layout.

hide_statusline
        Collapse native split statuslines into one blank global row while the
        ngit tab is active. If lualine is loaded, its statusline renderer is
        suspended. The previous statusline mode is restored when leaving or
        closing ngit.

file_panel_width
        A fraction below 1, or an absolute window width.

file_panel_height
        Retained for configuration compatibility. Dashboard panel heights are
        allocated automatically from the available editor height.

auto_refresh
        Refresh an open view after buffer writes, shell commands, and focus
        changes. Buffer writes reload working-tree status only; shell and focus
        events reload every repository collection.

confirm_discard
        Ask before restoring tracked worktree changes.

signs
        Text displayed for each file state.

mappings
        Buffer-local mappings. Set a mapping to false to disable it.

5. HIGHLIGHTING                                               *ngit-highlights*

Diff lines use NgitDiffAdd, NgitDiffDelete, and NgitDiffChange. Changed text
within a line uses NgitDiffAddText, NgitDiffDeleteText, or NgitDiffText.
NgitDiffAddNumber and NgitDiffDeleteNumber color source line-number markers.
Headers and alignment rows use NgitDiffHeader and NgitDiffFiller. Source
syntax highlighting is enabled when a preview contains one recognizable file
type.

Dashboard fields use NgitCommitHash, NgitCommitType, NgitDate, NgitDecoration,
NgitBranchLocal, NgitBranchRemote, NgitUpstream, NgitStashRef, NgitPath, and
NgitPathDim for the leading directories of a path. Commit metadata above a
patch uses NgitDiffMeta, and source line numbers use NgitLineNr.
File markers use the foreground-only NgitStagedSign, NgitUnstagedSign,
NgitUntrackedSign, and NgitConflictSign groups; the matching section headings
reuse them through NgitStaged, NgitUnstaged, NgitUntracked, and NgitConflict.
Panel headers use NgitPanelActive, NgitPanelMarker, NgitPanelMarkerIdle, and
NgitPanelCount, and the action bar uses NgitActionKey and NgitActionLabel.
Unfocused panels dim their selection through NgitCursorLineIdle.
All groups may be overridden after setup(). Theme-derived diff backgrounds are
recomputed after :colorscheme while they remain ngit-owned; an explicit user
override is preserved.

6. SAFETY AND PERFORMANCE                                         *ngit-safety*

Git is invoked asynchronously with argument arrays and literal pathspecs.
Read-only commands avoid optional repository locks. Status is parsed from
NUL-delimited porcelain-v2 output.

Changes, branches, commits, and stashes load independently and asynchronously.
Only the active panel's selected file, commit, branch, or stash preview is
loaded. Changing panel focus does not reload collection data. Commit history is
paginated. Rapid selection changes are debounced, superseded jobs are
terminated, and recent previews are stored in a cache bounded by both entry
count and estimated bytes. Oversized previews are displayed without caching.
Each raw patch is parsed once into a semantic presentation model, and the last
few models are retained so moving back over a file redraws without rebuilding
them. Toggling between split and unified presentation does not run another Git
command. Unified presentation is built lazily only when it is displayed. On
narrow screens the preview falls back to unified mode; editor areas smaller
than 40 columns by 16 lines are rejected before any dashboard tab is created.

Source line numbers are drawn through 'statuscolumn', so a patch costs nothing
for the rows that are never displayed. Syntax highlighting is skipped for very
large previews. Detecting an in-progress merge, rebase, cherry-pick, or revert
stats the git directory instead of spawning a process per refresh, and writes
outside the repository do not trigger one.

Every discard is confirmed and states its exact effect, deleting an untracked
file only when that is what was asked for. A file with unsaved changes in a
loaded buffer is never overwritten, and buffers are rechecked after any
mutation. Renames are acted on through both of their paths so no half-staged
entry is left behind. Branch deletion uses Git's merged-only behavior, pull is
fast-forward-only, and force push is not exposed. Remote progress appears in
a cancellable floating console.

Failures report what Git actually said. Several ordinary refusals arrive on
standard output rather than standard error, so both are considered before
falling back to an exit code. Committing checks for unresolved conflicts and
an empty index before opening an editor.
